Executive Architectural Overview: This platform demonstrates a resilient distributed transaction loop. Domain updates originate from the northwind-api-server (Spring Boot 3 REST API), execute atomic writes to PostgreSQL, get polled asynchronously by outbox_kafka_pipeline, post at least once to Apache Kafka validated by Apicurio Registry, and fan out to heterogeneous storage engines (MongoDB & AWS Lambda DynamoDB).

System Component Breakdown

An in-depth look at the operational logic, data paths, and technical decisions driving this architecture.

01

The Nervous System: Vanilla Kafka & Apicurio

Replace Confluent’s proprietary wrappers in favor of raw Apache Kafka paired with the open-source Apicurio Schema Registry v3.

  • Schema Governance: Apicurio REST endpoints provide strict schema validation without SaaS fees.
  • Zero Vendor Lock-In: Complete control over topics, consumer groups, and partition sizing.
  • Sovereign Infrastructure: Fully deployable on local Docker or enterprise Kubernetes clusters.
02

Reliable Messaging: Transactional Outbox Pattern

Solves the classic distributed commit problem between relational storage and message brokers.

  • Atomic Database Operations: northwind-api-server writes business domain data and outbox events into PostgreSQL via JDBC in a single transaction.
  • Guaranteed Delivery: (outbox_kafka_pipeline)) reads records and publishes to Kafka.
  • Fault Isolation: Network glitches between Kafka and DB never jeopardize domain transaction integrity.
03

Polyglot ELT Pipelines & Event Handlers

Demonstrating dual heterogeneous event consumers operating across containerized pods and serverless runtimes.

  • Kubernetes Document Stream: kafka_mongo_pipeline (Python pod) ingests customer/order events and streams transformed documents into MongoDB.
  • LocalStack Serverless Stream: kafka_dynamodb_pipeline (AWS Lambda in LocalStack) executes local serverless logic feeding items into DynamoDB.
04

Operational Resiliency & Failure Recovery

Ensuring poison-pill messages or downstream database timeouts don't block event stream processing.

  • Dead Letter Queue (DLQ): Unparseable events route to northwind-elt-events-dlq
  • Isolated Replay: Operational teams can inspect, repair, and replay failed messages without interrupting main stream processing.
  • Observability Ready: Clean separation of system errors from business domain events.
